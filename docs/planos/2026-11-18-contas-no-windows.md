# MAT-F2 · O plugin `contas` no Windows

**Pronto:** `npm test` do contas roda os testes de verdade e passa no Windows (e não quebra no Mac); o painel lê a cota e a troca de conta é testada à mão no app do Windows; docs no mesmo PR.

## O que foi medido nesta máquina (Windows 11, app 5.11492.5.0 da Microsoft Store)

- **Pasta do app:** `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc` (tem `config.json`, `Local State`, `Network\Cookies`, `claude-code-sessions\`). `%APPDATA%\Claude` e a pasta virtualizada do MSIX (`%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude`) só têm o marcador `.user-data-left.*`: o app mudou os dados de lugar. Os filhos do app recebem `--user-data-dir=` com essa pasta.
- **Chave:** `Local State` → `os_crypt.encrypted_key` (base64, prefixo `DPAPI`). `ProtectedData.Unprotect(..., CurrentUser)` pelo PowerShell dá 32 bytes em cerca de 0,5 s, sem aviso nenhum. `oauth:tokenCacheV2` é `v10` + nonce de 12 + cifra + tag de 16 (AES-256-GCM); decifrado, é o mesmo JSON do Mac (`acct:<uuid>|…` com `token` e `expiresAt`).
- **config.json:** releitura com tabulação idêntica ao original (sem `\n` final, sem CRLF): a conferência de formato vale igual.
- **Processos:** o app é `C:\Program Files\WindowsApps\Claude_<versão>_x64__pzs8sxrjxfjjc\app\Claude.exe` (processo principal sem `--type`). As sessões do Claude Code também se chamam `claude.exe` (`…\Claude-Data\…\claude-code\<versão>\…\claude.exe`), filhas do app. **Matar pelo nome derrubaria as sessões do Code e esta troca.**
- **Fechar:** fechar a janela principal só a esconde na bandeja (`menuBarEnabled`); o app sai limpo por `app.quit()` no evento `session-end` (fim de sessão do Windows). O caminho do Windows para pedir isso a um app é o Restart Manager (`RmShutdown`, que manda `WM_QUERYENDSESSION`/`WM_ENDSESSION` com `ENDSESSION_CLOSEAPP`).
- **Abrir:** `Start-Process "shell:AppsFolder\Claude_pzs8sxrjxfjjc!Claude"` (o pacote dá o `PackageFamilyName`; o Id da aplicação é `Claude`).
- **Job do pacote:** o app, as sessões do Code, os painéis e tudo que eles lançam (solto ou não) estão no mesmo Job do Windows. O app reiniciou às 12:58 e nenhum `node.exe`/`claude.exe` de antes sobreviveu, nem o Painel da orquestracao no ar desde as 11:15: **a troca lançada de dentro do app morreria no meio, com o app fechado.** O processo criado pelo WMI (`Win32_Process.Create`) nasce fora de qualquer Job (medido com `IsProcessInJob`). PowerShell lançado direto como `detached` (sem console) não roda nada; por um node, roda.
- **Testes:** com o glob certo, 254 testes, 42 falham. Causas: modo `0600/0700` (o Windows não guarda), `lastIndexOf('/')` em caminho com `\` (o nome do arquivo virava o caminho inteiro e o `join` montava pasta dentro de pasta), regex de caminho com `/`, `ps`/grupo de processo.

## Tarefas

1. **`package.json`** — tirar `"os": ["darwin"]`; glob entre aspas duplas (o cmd não tira aspas simples). *Risco: não.*
2. **Caminhos com `\`** — `conversas.mjs` (`basename` no nome da entrada; pasta do `cwd` por `/[\\/]/`), `sessoes.mjs` (idem). *Risco: não.*
3. **Pasta do app no Windows** (`app-do-claude.mjs`) — `CLAUDE_APP_DIR`; senão a primeira com `config.json` entre `%LOCALAPPDATA%\Claude-Data\claude_*`, `%APPDATA%\Claude` e `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude`; sem nenhuma, a primeira candidata (o erro de `semConfig` continua o mesmo). *Risco: não.*
4. **Controle do app no Windows** (`windows.mjs`, novo) — um PowerShell por ação (`-EncodedCommand`, sem arquivo e sem política de execução): `rodando` = algum processo cujo caminho é o `Claude.exe` do pacote (ou `AnthropicClaude\app-*\claude.exe` da instalação antiga), nunca pelo nome; `fechar` = `WM_QUERYENDSESSION`/`WM_ENDSESSION` com `ENDSESSION_CLOSEAPP` (o recado do Restart Manager) às janelas do processo principal, espera, e se não sair `Stop-Process -Force` **só nesses pids** (sem árvore: o CLI da troca e as sessões do Code não morrem por ela); `abrir` = `shell:AppsFolder` do pacote, ou o `claude.exe` da instalação antiga. `executar` injetável nos testes. *Risco: sim (fecha o app de quem usa).*
5. **Chave no Windows** (`uso.mjs`) — `lerChaveDoWindows`: lê `Local State`, tira o `DPAPI`, abre pelo PowerShell com o blob pelo ambiente do processo filho, devolve os 32 bytes; `decifrar` escolhe pelo tamanho da chave (16 → AES-128-CBC do Mac, 32 → AES-256-GCM do Windows). `atualizarUso`: `lerChave` injetado vale; `lerSenha` injetado segue o caminho do Mac; sem nenhum, o da plataforma. Erros sem repassar mensagem, como hoje. *Risco: sim (segredo).*
6. **Painel** — `cli.mjs`: `explorer.exe` para abrir; netstat + `Get-CimInstance` para quem escuta na porta (como `orquestracao/lib/pagina.mjs`); regex da linha de comando aceita `\`, `node.exe` e aspas. `contas.mjs`: `windowsHide` no filho solto; comando do pid pelo CIM; `src/troca/cli.mjs` conferido com `/` ou `\`. *Risco: não.*
6b. **Lançar fora do Job** — no Windows o painel lança a troca (e `abrir.mjs` sobe o painel) por `Win32_Process.Create`: `node --import solto.mjs <script> --pedido-solto <arquivo> <args>`. O pedido (0600, apagado ao ler) leva só as variáveis da troca (`CLAUDE_APP_DIR`, `TROCA_DE_CONTA_DIR`, `CLAUDE_CONFIG_DIR`…) e o log, nunca o ambiente inteiro; `solto.mjs` tira o argumento, aplica as variáveis e manda a saída ao log. A linha de comando continua a do script, que o painel reconhece. *Risco: sim.*
7. **Cancelar o "adicionar e voltar" no Windows** — o `SIGTERM` do Node no Windows mata na hora, sem o handler, e o app ficaria na tela de entrada. No Windows o painel grava `cancelar-adicionar` (com o pid) e o CLI, que já espera em laço, confere o arquivo a cada volta e aborta como o sinal. No Mac segue o sinal. *Risco: não.*
8. **Testes** — asserção de modo só fora do Windows (*assumida, a confirmar*: no Windows a pasta do usuário já é só dele pela ACL; não mexer em ACL); `ps`/grupo de processo e clone APFS só no Mac; regex de caminho com `[\\/]`. Testes novos: decifrar GCM, pasta do app no Windows, controle do Windows com `executar` falso, cancelamento por arquivo, `pidsEscutandoNaPorta`.
9. **Textos** — `regras.js` (`fraseDaChave` pela plataforma, que `GET /api/contas` passa a dizer), `app.js`/`index.html` ("neste Mac" → "neste computador"), `plugins/contas/README.md`, seção `contas` do `README.md` da raiz. *Risco: não.*
10. **À mão** — ler a cota no painel do Windows (não fecha nada). A troca fecha o app e corta todas as sessões do Code abertas nele (inclusive esta e a orquestradora), e trocar precisa de uma segunda conta logada, coisa que só o operador faz: esse teste é do operador, com o roteiro no PR.

Revisão: `orquestracao:revisor` (segredo + fecha o app). Consertado depois dela: "não sei se o app está aberto" (PowerShell sem resposta) nunca vale como fechado; os scripts filtram pela sessão do Windows; o WMI cria o processo com `ShowWindow = 0` (medido: sem ele abre uma janela do Windows Terminal, e fechá-la mataria a troca); o filho do WMI deixa de valer quando deixa desfecho ou perde a trava (pid reaproveitado); o pedido de cancelar de outro processo vivo fica para ele; erro fatal do processo do WMI vai ao log; testes conferem o texto dos scripts de matar e fechar, compilam o C# e rodam o filtro real.
